# 基于 AI 协同开发的任务管理系统设计与实现实验报告

## 1. 实验内容、要求或目的

本次实验的任务是使用 Go 语言设计并实现一个小型任务管理系统，系统以后端功能实现为主，采用命令行程序进行功能展示。系统应围绕"任务"的管理展开，完成基本的数据操作，并实现数据持久化存储。

实验目的：
1. 熟悉 Go 语言在小型系统开发中的基本使用方法
2. 掌握结构体、函数、文件组织等基本程序设计的方式
3. 理解数据持久化在应用程序中的基本作用
4. 学习利用 AI 工具辅助完成程序开发的基本流程
5. 提高综合设计、实现与实验总结能力

## 2. AI 参与过程

在本次实验中，我使用了 AI 工具辅助完成以下工作：

1. **需求整理**：通过与 AI 对话，明确了任务管理系统的核心功能和数据结构设计。
2. **数据结构设计**：AI 帮助设计了 Task 结构体，包含任务编号、名称、描述、状态、优先级和创建时间等字段。
3. **代码生成**：AI 生成了任务管理系统的核心代码，包括模型层、DAO 层、服务层和控制器层。
4. **Bug 调试**：在编译过程中遇到了一些错误，AI 帮助分析并解决了这些问题，例如未使用的导入包和空文件导致的编译错误。
5. **功能优化**：AI 提供了一些优化建议，例如代码结构的组织和错误处理的改进。

使用过程中遇到的问题：
- 编译错误：由于空文件导致的编译错误，通过为这些文件添加基本的包声明解决。
- 数据库连接：需要确保 MySQL 数据库服务正在运行，并且连接字符串正确。

对 AI 结果的修改或调整：
- 移除了未使用的导入包
- 为控制器层添加了更友好的用户交互界面
- 优化了错误处理逻辑

## 3. 程序主要算法或源代码

### 核心模块说明

1. **模型层 (model/task.go)**
   - 定义了 Task 结构体，包含任务的基本信息
   - 使用 JSON 标签方便数据序列化

2. **DAO 层 (dao/task_dao.go)**
   - 负责数据库操作，包括创建、查询、更新和删除任务
   - 使用参数化查询防止 SQL 注入

3. **服务层 (service/task_service.go)**
   - 处理业务逻辑，调用 DAO 层方法
   - 提供简洁的接口给控制器层

4. **控制器层 (controller/task_controller.go)**
   - 处理命令行交互，接收用户输入
   - 调用服务层方法执行相应操作
   - 显示操作结果给用户

5. **主程序 (main.go)**
   - 初始化数据库连接
   - 创建任务表
   - 初始化各个层的实例
   - 提供命令行菜单交互

### 关键代码

#### 任务数据结构
```go
// Task 任务数据结构
type Task struct {
	ID          int       `json:"id"`
	Name        string    `json:"name"`
	Description string    `json:"description"`
	Status      string    `json:"status"`
	Priority    string    `json:"priority"`
	CreatedAt   time.Time `json:"created_at"`
}
```

#### 创建任务
```go
// CreateTask 创建任务
func (s *TaskService) CreateTask(name, description, status, priority string) (*model.Task, error) {
	task := &model.Task{
		Name:        name,
		Description: description,
		Status:      status,
		Priority:    priority,
		CreatedAt:   time.Now(),
	}

	err := s.TaskDAO.Create(task)
	if err != nil {
		return nil, err
	}

	return task, nil
}
```

## 4. 实验结果与分析

### 系统运行结果

系统成功启动，显示了任务管理系统的菜单，用户可以通过输入数字选择相应的操作。

1. **创建任务**：用户输入任务名称、描述、状态和优先级，系统将任务保存到数据库中。
2. **查询任务**：支持根据 ID、状态和优先级查询任务，以及查询所有任务。
3. **更新任务**：用户输入任务 ID 和新的任务信息，系统更新数据库中的任务。
4. **删除任务**：用户输入任务 ID，系统从数据库中删除相应的任务。

### 功能分析

系统实现了所有基础功能要求：
- 任务数据结构设计：包含了任务编号、名称、描述、状态、优先级和创建时间
- 任务新增功能：能够创建任务并保存到数据库中
- 任务查询功能：支持查询全部任务、按编号查询、按状态或优先级查询
- 任务修改功能：支持对已有任务进行信息修改
- 任务删除功能：支持根据编号删除任务
- 数据持久化：使用 MySQL 数据库实现数据持久化存储
- 系统运行演示：能够完整演示基本业务流程
